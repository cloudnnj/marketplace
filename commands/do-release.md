# Execute Release

You are a release automation expert. Execute the following release workflow for version **$ARGUMENTS**.

## 1. Organize Prompt Files (Incremental)

Only organize prompt files that are **new or modified since the previous release tag**. Do NOT re-read, re-classify, or re-sequence files from prior releases.

### Steps:
```bash
# Find the previous release tag
PREV_TAG=$(git describe --tags --abbrev=0 2>/dev/null || echo "")

if [ -z "$PREV_TAG" ]; then
  echo "No previous tag found — processing all prompt files"
  NEW_BUILD_FILES=$(git ls-files -- prompts/build/)
  NEW_BUGFIX_FILES=$(git ls-files -- prompts/bugfix/)
else
  echo "Previous release: $PREV_TAG"
  NEW_BUILD_FILES=$(git diff --name-only "$PREV_TAG"..HEAD -- prompts/build/)
  NEW_BUGFIX_FILES=$(git diff --name-only "$PREV_TAG"..HEAD -- prompts/bugfix/)
fi
```

1. Identify only the new/modified prompt files using the commands above
2. Read each **new** file and classify as feature or bugfix
3. Find the current highest sequence number in each directory
4. Append new files after the existing sequence — do NOT re-sequence existing files
5. Move misclassified bugfix files from `prompts/build/` to `prompts/bugfix/`

## 2. Update Documentation

Delegate documentation updates to the standalone command:

> Execute the steps defined in `.claude/commands/update-user-guide.md` inline to update documentation files scoped to changes since the previous release.

## 3. Update Repository Statistics

```bash
npm run stats
```

Updates the lines-of-code table and merged PR count in `README.md` between the `<!-- STATS:START -->` and `<!-- STATS:END -->` markers.

## 4. Generate Release Notes (Incremental)

Create `docs/releases/v$ARGUMENTS.md` with **only the current release's changes**.

Use prompt files organized in Step 1 (new since `$PREV_TAG`) to populate features and bug fixes. If no previous tag exists, include all prompt files.

```markdown
# Release v$ARGUMENTS

**Release Date:** [Current Date]

## Summary
[Brief overview based on NEW prompts from this release only]

## Features
[One bullet per NEW feature prompt]

## Bug Fixes
[One bullet per NEW bugfix prompt]

## Breaking Changes
[List any breaking changes, or "None"]

## Contributors
- Organization Release Manager (automated)

---
*Generated by Organization Release Manager*
```

## 5. Update Version Number

```bash
npm version $ARGUMENTS --no-git-tag-version
```

## 6. Important Notes

- Do NOT create git commits - the calling system handles version control
- Only process NEW prompt files since the previous release tag
- Preserve existing file structure and formatting conventions
- Create any necessary directories (e.g., `docs/releases/`, `prompts/bugfix/`)
